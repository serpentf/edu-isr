# Заключение курса

## Итоги

Ручное и автоматизированное тестирование решают разные задачи и дают наилучший результат вместе.

- **Ручное тестирование** даёт гибкость и человеческое чутьё, но медленно при повторах.
- **Автоматизация** экономит время на регрессии, но требует затрат на разработку и поддержку и окупается лишь при частых запусках.
- **Пирамида тестирования** подсказывает, что автоматизировать в первую очередь: модульные и API-тесты.
- **Методы тест-дизайна** (граничные значения, классы эквивалентности) одинаково полезны в обоих подходах.
- **Инструменты** выбираются исходя из технологий продукта, бюджета и квалификации команды.

## Главный принцип

> **Не автоматизируйте хаос.** Сначала добейтесь стабильности ручного процесса, затем автоматизируйте самые частые и критичные проверки.

## Карта курса

| Модуль | Ключевая идея |
|--------|---------------|
| 1. Введение | Чем позже найден дефект, тем дороже; подходы дополняют друг друга |
| 2. Ручное тестирование | Человек незаменим там, где важны восприятие и новизна |
| 3. Автоматизация | Тест — это код; пирамида: много unit, мало UI |
| 4. Экономика | N = C<sub>разработки</sub> / (C<sub>ручного</sub> − C<sub>поддержки</sub>) |
| 5. Организация | Тест-дизайн, уровни, жизненный цикл дефекта, документация |
| 6. Инструменты | Выбор под стек, команду и бюджет; BDD связывает требования и тесты |
| 7. Тенденции | CI/CD, shift-left и shift-right, контракты, контейнеры, ИИ |
| 8. Стратегия | Смешанный подход; автоматизация внедряется по шагам |
