# Инструменты автоматизации

## Цель урока

Сориентироваться в инструментах автоматизации по типам тестирования и усвоить критерии выбора.

## Обзор

| Тип | Инструменты |
|-----|-------------|
| Модульное | JUnit (Java), PyTest (Python), NUnit (C#), Jest, Mocha (JavaScript) |
| API | Postman + Newman, REST Assured, SoapUI, Karate |
| UI Web | Selenium WebDriver, Cypress, Playwright, Puppeteer |
| UI Mobile | Appium, Espresso (Android), XCUITest (iOS) |
| Нагрузочное | JMeter, Gatling, k6, Locust, Yandex.Tank |
| BDD-фреймворки | Cucumber, Behave, SpecFlow |
| CI/CD | Jenkins, GitLab CI, GitHub Actions, TeamCity |
| Отчёты | Allure Framework, ReportPortal, ExtentReports |

## Как не потеряться

**Модульные фреймворки привязаны к языку.** Модульные тесты пишут на языке продукта, поэтому выбор почти предопределён: Java → JUnit, Python → PyTest, C# → NUnit, JavaScript → Jest или Mocha.

**API.** Postman удобен для ручных проверок. Его коллекции можно запускать автоматически через **Newman** в командной строке и в CI. REST Assured — библиотека для Java, Karate позволяет описывать API-тесты в стиле BDD.

**UI Web.** Selenium WebDriver — исторический стандарт с поддержкой многих языков и браузеров. Cypress, Playwright и Puppeteer — более новые инструменты со встроенным ожиданием элементов и удобной отладкой.

**UI Mobile.** Appium — кроссплатформенный инструмент для Android и iOS. Espresso и XCUITest — нативные фреймворки платформ: они быстрее и стабильнее, но требуют писать тесты отдельно под каждую ОС.

**Нагрузочное.** JMeter — классический инструмент с графическим интерфейсом. Gatling, k6 и Locust описывают сценарии нагрузки кодом (Scala/Java, JavaScript, Python), а Yandex.Tank — консольный инструмент от Яндекса.

**CI/CD и отчёты** связывают всё вместе: CI-сервер запускает тесты на каждый коммит, а Allure или ReportPortal собирают результаты в наглядный отчёт с историей и вложениями.

## Критерии выбора

1. **Технологический стек продукта** — язык, фреймворк, платформа (веб, мобильная, десктоп).
2. **Квалификация команды** — инструмент на знакомом языке внедрится быстрее.
3. **Бюджет** — большинство перечисленных средств автоматизации бесплатны и с открытым кодом, но коммерческие решения дают поддержку и готовую инфраструктуру.
4. **Интеграция** — запуск в используемом CI и выгрузка отчётов.
5. **Сообщество и документация** — насколько легко найти ответ на вопрос.

## Главное

- Модульные фреймворки определяются языком продукта.
- Для каждого уровня пирамиды есть свои инструменты, CI и отчёты связывают их вместе.
- Выбор определяют стек, команда и бюджет.
