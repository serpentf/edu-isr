# Тест-дизайн

## Цель урока

Освоить шесть техник тест-дизайна, которые позволяют проверить много при небольшом числе тестов.

## Зачем нужен тест-дизайн

Проверить все возможные входные данные невозможно: поле, принимающее число от 1 до 1 000 000, даёт миллион вариантов, а несколько полей — их произведение. Тест-дизайн — это способ выбрать **минимальный набор проверок с максимальной вероятностью найти ошибку**.

## 1. Эквивалентное разбиение

Входные данные делятся на **классы**, внутри которых система ведёт себя одинаково. Из каждого класса берётся **одно значение**: если система верно обработала 30, то и 31 она обработает так же.

## 2. Анализ граничных значений

Проверяются **минимум, максимум и значения чуть выше и ниже границы**. Именно на границах чаще всего возникают ошибки: разработчик написал `<` вместо `<=` или `>` вместо `>=`.

### Пример: поле «Возраст» принимает значения от 18 до 65

| Класс эквивалентности | Диапазон | Граничные значения для теста | Ожидаемый результат |
|-----------------------|----------|------------------------------|---------------------|
| Ниже допустимого | до 17 | 17 | Ошибка |
| Допустимые | 18–65 | 18, 19, 64, 65 | Принято |
| Выше допустимого | от 66 | 66 | Ошибка |
| Некорректный тип | буквы, пусто | «абв», «» | Ошибка |

Вместо 100+ возможных чисел — **8 проверок**, которые покрывают все классы и все границы. Обычно эти две техники применяют вместе: классы задают, *что* проверять, границы — *какие именно* значения брать.

## 3. Попарное тестирование (pairwise)

Когда параметров много, полный перебор комбинаций взрывается. Попарное тестирование перебирает **все пары значений** параметров вместо всех комбинаций. Большинство дефектов вызывается сочетанием одного или двух параметров, а не трёх и более.

**Пример:** 3 браузера × 3 ОС × 3 языка = **27 комбинаций**, а попарное покрытие достигается **9 тестами**:

| № | Браузер | ОС | Язык |
|---|---------|----|------|
| 1 | Chrome | Windows | RU |
| 2 | Chrome | macOS | EN |
| 3 | Chrome | Linux | DE |
| 4 | Firefox | Windows | EN |
| 5 | Firefox | macOS | DE |
| 6 | Firefox | Linux | RU |
| 7 | Edge | Windows | DE |
| 8 | Edge | macOS | RU |
| 9 | Edge | Linux | EN |

Возьмите любые два столбца: каждая пара их значений встречается ровно один раз. Такие наборы строят инструменты, например PICT или allpairs.

## 4. Таблицы решений

Для **бизнес-правил с несколькими условиями**. Каждый столбец — одна комбинация условий и ожидаемое действие.

**Пример:** бесплатная доставка положена, если сумма заказа от 3000 ₽ **или** у клиента есть подписка.

| Условие / правило | П1 | П2 | П3 | П4 |
|-------------------|----|----|----|----|
| Сумма ≥ 3000 ₽ | Да | Да | Нет | Нет |
| Есть подписка | Да | Нет | Да | Нет |
| **Доставка бесплатна** | **Да** | **Да** | **Да** | **Нет** |

Четыре правила — четыре теста. Таблица также помогает найти пробелы в требованиях: если для какой-то комбинации никто не знает ответа, это вопрос к аналитику.

## 5. Тестирование переходов состояний

Для систем, поведение которых **зависит от состояния**. Пример — заказ:

```
Создан → Оплачен → Отправлен → Доставлен
```

Проверяются:

- **допустимые переходы** — каждый шаг цепочки;
- **недопустимые переходы** — нельзя отправить неоплаченный заказ, нельзя «доставить» только что созданный;
- **действия в каждом состоянии** — например, можно ли изменить адрес у отправленного заказа.

## 6. Предугадывание ошибок (error guessing)

Проверки **на основе опыта**: тестировщик знает, где обычно ломаются системы. Классический набор:

- пустые поля и строка из пробелов;
- спецсимволы: `' " < > & ; --`;
- очень длинные строки;
- ноль, отрицательные и дробные числа;
- эмодзи и нелатинские символы;
- двойной клик по кнопке отправки.

## Главное

- Классы эквивалентности и граничные значения сокращают число проверок без потери качества.
- Pairwise покрывает все пары параметров: 27 комбинаций → 9 тестов.
- Таблицы решений — для правил с условиями, переходы состояний — для объектов с жизненным циклом.

## Вопросы для самопроверки

1. Поле принимает от 1 до 10 товаров. Какие значения вы проверите методом граничных значений?
2. Почему на границах диапазонов ошибки встречаются чаще всего?
3. Добавьте в таблицу решений условие «товар крупногабаритный — доставка всегда платная». Сколько стало правил?
