# Тестовая документация и хранение тестов

## Цель урока

Познакомиться с основными видами тестовой документации и узнать, где хранятся ручные тесты и автотесты.

## Четыре вида документов

| Документ | Содержание | Когда нужен |
|----------|-----------|-------------|
| **Тест-план** | Цели, объём, подход, критерии начала и окончания, риски | В начале проекта или релиза: договориться, что и как тестируем |
| **Чек-лист** | Краткий список проверок без детальных шагов | Опытная команда, smoke и sanity, быстро меняющийся продукт |
| **Тест-кейс** | Предусловия, шаги, ожидаемый результат | Сценарное и регрессионное тестирование, будущая автоматизация |
| **Отчёт о тестировании** | Что проверено, сколько дефектов, рекомендация о выпуске | В конце цикла: дать основание для решения о релизе |

### Чек-лист или тест-кейс?

Пример чек-листа для формы входа:

- [ ] вход с верными данными;
- [ ] вход с неверным паролем;
- [ ] вход с пустыми полями;
- [ ] блокировка после 5 неудачных попыток.

Тот же первый пункт в виде тест-кейса:

| Поле | Значение |
|------|----------|
| ID | TC-AUTH-001 |
| Название | Успешный вход с верными учётными данными |
| Предусловия | Пользователь user@test.ru зарегистрирован, пароль Secret123 |
| Шаги | 1. Открыть /login. 2. Ввести email и пароль. 3. Нажать «Войти». |
| Ожидаемый результат | Открыт личный кабинет, в шапке отображается имя пользователя |

Чек-лист быстрее писать и поддерживать, но результат зависит от того, кто его выполняет. Тест-кейс воспроизводим и почти напрямую превращается в автотест по схеме [AAA](../../03-automated-testing/lessons/04-test-structure.md) (модуль 3).

## Где хранятся тесты

**Ручные тесты** хранятся в системах управления тестированием (**TMS**): TestRail, Zephyr, Qase, Allure TestOps. TMS позволяют группировать тест-кейсы, планировать тестовые прогоны, отмечать результаты и строить отчёты.

**Автотесты — это код**, и обращаются с ними как с кодом:

- живут в **Git** рядом с кодом продукта или в отдельном репозитории;
- запускаются в **CI**: Jenkins, GitLab CI, GitHub Actions;
- результаты попадают в **отчёты**: Allure, ReportPortal.

```
Код + автотесты (Git) → CI-сервер запускает тесты → отчёт (Allure, ReportPortal)
```

## Главное

- Тест-план отвечает на вопрос «как будем тестировать», отчёт — «можно ли выпускать».
- Чек-лист — краткий и гибкий, тест-кейс — подробный и воспроизводимый.
- Ручные тесты живут в TMS, автотесты — в Git и CI.
