# Непрерывное тестирование, shift-left и shift-right

## Цель урока

Понять, как тестирование встраивается в каждый шаг разработки: от требований до продакшена.

## Непрерывное тестирование в CI/CD

**Каждый коммит запускает сборку и автотесты.** Код с упавшими тестами не попадает в основную ветку. Такое правило называется **quality gate** («ворота качества»).

```
Коммит → Сборка → Модульные тесты → API-тесты → UI-тесты → Слияние в main → Выпуск
             ✗ любой шаг упал → слияние заблокировано, автор получает уведомление
```

Что это даёт:

- ошибка обнаруживается **через минуты** после её внесения, пока автор помнит контекст;
- основная ветка **всегда в рабочем состоянии**;
- регрессия проверяется постоянно, а не раз в релиз.

Порядок шагов повторяет пирамиду: быстрые модульные тесты идут первыми и отсекают большинство ошибок, медленные UI-тесты запускаются последними.

## Shift-left: сдвиг влево

Если нарисовать жизненный цикл слева направо (требования → код → тестирование → эксплуатация), **shift-left** — это перенос тестирования **к ранним этапам**. Цель — находить дефекты там, где они дешевле всего (вспомните модуль 1).

Практики:

- **Ревью требований** — тестировщик участвует в обсуждении требований и задаёт вопросы «а что, если…» до написания кода.
- **TDD (Test-Driven Development)** — тест пишется **до кода**: сначала падающий тест, затем минимальный код, чтобы он прошёл, затем рефакторинг.
- **Статический анализ** — **SonarQube**, линтеры: проверка кода без его запуска (потенциальные ошибки, уязвимости, дублирование).

## Shift-right: сдвиг вправо

**Shift-right** — проверки **в продакшене**. Никакое тестовое окружение не воспроизводит реальных пользователей, данные и нагрузку полностью, поэтому часть проверок переносится в эксплуатацию.

| Практика | Суть |
|----------|------|
| **Мониторинг** | Метрики, логи и алерты показывают ошибки и деградацию в реальном времени |
| **A/B-тесты** | Две версии функции показывают разным группам пользователей и сравнивают результат |
| **Канареечные релизы** | Новая версия сначала выкатывается на небольшую долю пользователей; если метрики в норме, — на всех |
| **Feature flags** | Новая функция включается и выключается переключателем без нового релиза |

Shift-left и shift-right не противоречат друг другу: первый предотвращает дефекты, второй быстро обнаруживает и ограничивает последствия тех, что всё же прошли.

## Главное

- В CI/CD каждый коммит проходит автотесты, quality gate блокирует сломанный код.
- Shift-left: ревью требований, TDD, статический анализ.
- Shift-right: мониторинг, A/B-тесты, канареечные релизы, feature flags.
