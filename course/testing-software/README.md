# Курс: Ручное и автоматизированное тестирование ПО

> Основано на докладе «Ручное и автоматизированное тестирование. Методы и средства организации тестирования» (`internal-doc/Ручное и автоматизированное тестирование ПО.docx`).

## О курсе

Курс охватывает оба основных подхода к тестированию ПО — ручное и автоматизированное — и учит выстраивать смешанную стратегию тестирования, оптимальную для проекта: что проверять человеку, что автоматизировать, когда автоматизация окупается и как её внедрять.

**Уровень:** начальный · **Длительность:** ≈ 14 часов · **Формат:** теория, практические задания, тесты по модулям, итоговый проект.

## Для кого

- Начинающие тестировщики (QA Engineer / QA Intern)
- Разработчики, пишущие автотесты
- Тимлиды и менеджеры проектов, планирующие стратегию тестирования
- Все, кто хочет систематизировать знания о тестировании

## Как проходить

1. Изучите теорию модуля и ответьте на вопросы для самопроверки в конце каждого урока.
2. Выполните практическое задание — у каждого есть критерии оценки.
3. Пройдите тест по модулю (зачёт — 70% правильных ответов).
4. В конце выполните итоговый проект и итоговый тест.

## Итоговые знания

После прохождения курса вы сможете:

- различать ручное и автоматизированное тестирование и понимать, когда каждый подход уместен;
- применять методы тест-дизайна: классы эквивалентности, граничные значения, pairwise, таблицы решений, переходы состояний;
- выстраивать пирамиду тестирования и писать автотесты по схеме AAA;
- рассчитывать окупаемость автоматизации;
- выбирать инструменты под стек технологий;
- выстраивать смешанную стратегию тестирования и план внедрения автоматизации;
- ориентироваться в современных тенденциях: CI/CD, shift-left/right, контрактное тестирование, ИИ.

Порядок уроков задаётся числовым префиксом. Название урока — первый заголовок `#` в файле.

### Задания на JavaScript (`*.challenge.md`)

Студент пишет тесты для данной функции; проверка — мутационная. Тесты должны пройти на правильной реализации и упасть на каждой реализации с внесённым багом («мутанте»). Код задания хранится в помеченных блоках, которые при сборке убираются из текста урока:

| Блок | Содержание |
|------|-----------|
| ` ```js @subject ` | Правильная реализация. Для `kind: function` студент видит её код, для `kind: api` — только API-консоль |
| ` ```js @starter ` | Заготовка в редакторе |
| ` ```js @solution ` | Эталонные тесты (показываются после выполнения) |
| ` ```js @mutant <подсказка> ` | Реализация с багом; подсказка видна студенту. Блоков может быть несколько |
| ` ```json @config ` | Настройки, см. ниже |

Поля `@config`:

| Поле | Значение |
|------|----------|
| `minTests` | Минимальное число тестов (по умолчанию 1) |
| `kind` | `function` (по умолчанию) — тесты вызывают функции из `@subject`; `api` — `@subject` объявляет `createServer()`, который возвращает обработчик `req → { status, body }`. Тесты обращаются к нему через `api.get/post/put/delete`, а сервер пересоздаётся перед каждым тестом |
| `examples` | Для `kind: api` — кнопки-примеры в API-консоли: `{ method, path, body?, authorization? }` |
| `mutantMode` | `override` — блок `@mutant` содержит только переопределённые функции и дописывается к `@subject`: позднее объявление функции заменяет раннее. Удобно, когда реализация большая, а баг — в одной функции |

Доступны `test`, `beforeEach`, `expect(...)` с `toBe`, `toEqual`, `toBeCloseTo`, `toBeTruthy`, `toBeFalsy`, `toBeGreaterThan`, `toBeLessThan`, `toThrow`, модификатор `.not` и `console.log`. Скрипт сборки прогоняет `@solution` тем же движком, что и браузер, и падает, если эталон не проходит или не ловит какого-то мутанта, а также если заготовка засчитывается без изменений.

## Загрузка на платформу Edu ISR

Курс собирается в SQL-скрипт для базы платформы:

```bash
node scripts/build-course-seed.js course/testing-software
docker exec -i edu_isr_mysql mysql -uedu_user -pedu_password edu_isr < docker/mysql/seed-testing-software.sql
```

В базе должен быть хотя бы один пользователь с ролью `admin`: он станет автором курса. Скрипт создаёт курс, модули и уроки (текст, практика, тесты) в одной транзакции и копирует изображения в `frontend/public/courses/testing-software/`. Для повторной загрузки сначала удалите курс с этим slug.
